# Architecture

`document` normalizes text, splits paragraphs and bounded sentence fragments, constructs chapter indices and computes content identities. It contains no file, speech or network integration. `extract` reads only explicitly selected documents, performs bounded TXT/DOCX/EPUB extraction and rejects unsupported formats. Extracted text is reflowed; document layout is not preserved.

`playback::Player<A>` is a transport state machine over an `Audio` trait. Completion, pause, resume, stop and cursor advancement can be verified with a silent adapter. SAPI owns synthesis and timing; no guessed word timestamps are displayed. Native `WaitUntilDone(0)` uses the raw HRESULT because its generated Rust wrapper treats both S_OK and S_FALSE as success.

`speech::Sapi` creates and owns COM interfaces on a dedicated MTA worker. The idle/paused worker blocks on its bounded command queue. During playback it checks completion at 40 ms intervals while retaining command responsiveness. Application generations discard stale position/state events after navigation or document replacement. A separately constructed SAPI voice exports PCM WAV on the file worker without audio-device output. Export works one fragment at a time, checks cancellation and has a two-minute engine timeout per fragment.

If initial playback fails with SAPI `SPERR_NOT_FOUND`, the adapter retries with a directly created `SpMMAudioOut` using `WAVE_MAPPER`, the current Windows default playback output. This handles a missing SAPI default audio token without changing Windows settings. File output is explicitly marked and can never enter that speaker fallback. Export finalization releases its rendering voice before closing the stream while retaining a COM apartment guard. It does not reset the voice to the default audio output, so successful synthesis can finish even if that output token is unavailable. This fixes a failure reproduced with Microsoft Zira Desktop during the native follow-up.

The UI uses egui 0.33.3, egui-winit, egui_software_backend 0.0.2 and softbuffer 0.4.8. CPU rasterization produces a retained BGRA bitmap; softbuffer's Windows implementation presents it using GDI `BitBlt`. The application no longer creates an OpenGL/DirectX renderer. Windows desktop composition remains an OS responsibility. A custom winit host uses `ControlFlow::Wait` / `WaitUntil` and ignores stale repaint callbacks by cumulative egui pass number. OS expose events can reuse the retained bitmap without reconstructing or rasterizing the scene.

The Windows SDK resource compiler embeds the application ICO through `build.rs` as neutral-language `RT_ICON` / `RT_GROUP_ICON` resources. The same original book mark has 16–256 px variants for shell scaling. A compiled-in PNG is decoded once during native window construction and supplied as both window and taskbar icons; no icon file reads or allocations are added to the frame loop. The icon resource is checked directly in the packaged executable.

Normal hidden/minimized windows process background results and save pending changes without building UI or rasterizing. A restore/resize invalidates the scene once. Layout/raster/presentation counters and separate timings are aggregated in memory for bounded diagnostics. No sleep, permanent polling loop or frame-rate cap substitutes for correct scheduling.

The reading room presents up to five bounded passages per page with full wrapping and a scrollable paper surface. Only the current page is laid out. Contents/bookmarks are in the left rail, common document actions are in the header, and a single Play/Pause/Resume action anchors the bottom player. Settings retain voice, speed, text size, installed version, update controls and local data information. This is a sustained reading workspace, so a tray-only interface would obscure the core task.

The app has four persistent workers: speech, selected-file import/export/dialogs, network and session storage. Commands are bounded, and the UI uses nonblocking sends. Network checking does not block file import or session saving. The session queue holds at most one snapshot; documents use shared immutable `Arc` storage so a save snapshot does not clone megabytes of text on the UI thread. Export/download progress is coalesced to whole percentages. Shutdown cancels export, stops speech and saves before allowing the close event. Forced termination or OS shutdown can still lose the most recent unsaved cursor.

The UI can edit settings/bookmarks during normal saving. Dirty state is retained if a later change occurs after a snapshot was queued. Saved progress is the start of the current passage, not a sample-accurate speech offset. Error loading an existing session disables overwrites for that launch. Save failures remain visible rather than silently discarding the original. An optional `TextReader.data` directory next to the EXE selects portable storage; without it, LocalAppData remains the default.

`--screenshot` is an isolated, finite render-save-exit mode using the same components, theme, fonts and CPU rasterizer. It creates no native window, starts no workers, loads no user profile and makes no update/audio requests. Four finite frames settle layout/font uploads/window animations; the final client bitmap is saved as PNG. It verifies static rendering, not native chrome or interaction. `--diagnose` runs an isolated populated fixture through visible, minimized and restored phases with timings, CPU and frame counters; it exits after the bounded schedule. Neither mode adds a consumer settings surface or automation server.

`updater` is a product adapter for the sibling `rust-auto-updator` core. It specifies the canonical repository, installed product version, maximum executable size and staging/helper names. Shared code selects stable releases, requires `TextReader-vVERSION.exe` and `SHA256SUMS.txt`, verifies repository binding, size, digest and PE architecture, then stages next to the installed EXE. The application saves its session before moving ownership of the prepared download to the network worker for handoff. The downloaded EXE acts as the native helper, waits up to 45 seconds for the original process, verifies the target identity/hash, replaces on the same volume and relaunches with a validated cleanup directory. Failed restart restores the previous executable. The host routes helper arguments before initialization and cleans validated staging after successful window initialization. No credentials, shell script, elevation or user-data paths are needed by the shared installer.

Current boundaries: no document library UI, source editing, PDF extraction, OCR, DRM, cloud TTS, model downloads, SSML input, MP3, exact word alignment, system-wide selected-text reading, tray mode or multi-instance coordination. The app does not automatically reopen source paths or resume audio at startup; it restores cached text only.
